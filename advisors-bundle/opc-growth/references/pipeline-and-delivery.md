# 从咨询到验收的服务流程

适用：已有服务但成交、交付或返工不稳定时。

## 用状态而非感觉管理机会

线索、已诊断需求、已提交方案、已接受条款、已付款、已交付、已验收分别记录。客户回复“不错”不等于接受方案，发出文件不等于验收完成。每一阶段需要可观察的进入/退出条件。

| 阶段 | 核心问题 | 留底 |
|---|---|---|
| 需求诊断 | 最近哪里卡住，现有方案为何不足？ | 问题摘要、限制、决定人 |
| 提案 | 解决什么，不解决什么？ | 交付范围、验收、价格与条件 |
| 启动 | 输入和协作条件是否齐？ | 材料责任、节点、沟通约定 |
| 执行与内审 | 事实、权限、质量是否可核对？ | 版本、证据、问题及修复 |
| 交付验收 | 客户能否按预期使用？ | 实际反馈、未解决项、接受状态 |

## 先定位流失环节

咨询多而方案少可能是人群不匹配或需求不清；方案多而成交少可能是价值、范围、信任或预算问题。要查同一批机会的实际记录，不能套通用“健康转化率”给业务判死刑。

合成例：资料整理服务频繁返工。核对后发现客户认为包含重新撰写，而提供者只计划整理。改进首先是样例、排除项和验收标准，不是增加自动化工具。

## 变更单

新要求出现时记录原范围、新增内容、工时/费用/交期影响、是否同意。不要静默加班吞下所有变更，也不把合理修错都收费。重要承诺保留可回读确认，不替未同意的人签字。

公开案例需独立取得授权并核对可公开程度。客户真实数据、联系人、内部效果和业务错误不因制作案例就自动可披露。AI可整理草稿，不在本页授权下代发私信或建立自动跟进。
