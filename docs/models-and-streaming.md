# 可用模型与实时反馈

输入框下方的“本轮模型”列出当前 Codex 连接提供的型号，以及已经通过真实调用验证的独立模型路由。Codex 目录提供的型号可以直接选择，尚无独立连接检查回执时标注“目录提供”；实际对话成功以会话回执为准，这与独立连接检查分开记录。独立路由（例如 Gemini）需要先验证。选择只影响下一轮，不更改 Codex 全局默认模型。发送时重新核对目录、连接指纹与当前文档权限；取得实际线程模型回执并匹配后才提交问题和资料。

模型目录由实际连接的 Codex CLI 提供。若设置中未指定专用 CLI，工作台会比较 PATH 与标准 macOS 官方桌面应用内已安装 CLI 的可核实版本，使用较新的一个；显式配置始终优先。旧 CLI 可能只返回较早的内置目录，即使同机另一客户端已有新模型。点击“刷新模型目录”会跳过工作台短时目录缓存，重新读取当前连接，不发生成请求；它不会凭模型名称把目录未提供的条目标成可用。

新安装或连接变化后，点击“检查连接”或“连接与留底 → 检查可用模型”。检查使用固定的公开测试句，不发送用户草稿、知识库或个人资料。依次检查本机显式默认模型及 Gemini 候选；每个有时间上限，可停止。独立路由只有验证成功后才可选择；Codex 当前目录提供的型号不要求预先试答。失败项保留检查结果，不会静默切换模型或丢弃草稿。历史成功回执显示验证时间，不等于永久可用或额度保证；验证文件属于私人数据，不随源码分发。

主工作区通过 app-server 的持久 thread/turn 继续对话，不再仅拼接最近12条消息。传输进程按调用释放，持久线程标识保留。资料按需要通过受限动态工具检索、读取；实际读取记入资料证据；完整读取顾问 Skill 后，模型通过 select_advisor 明确选用并给出理由，才进入“本轮顾问”。读过与选用分别记录。不会为每个问题预先强制调用一次独立选顾问模型。

实时反馈区分应用工具事件、模型主动提供的公开工作说明/摘要、回答正文。原始内部思维内容不转发，没有公开摘要时不使用固定文字冒充。流式内存快照有节流，工具完成后保存检查点，普通正文定期保存，降低持续输出对本机的负担。

历史消息和会话列表按游标分页查询；这只是界面加载方式，不会删除底层消息或缩短持久模型线程。取消、失败和重启中断均保留实际状态。

完成消息保留模型标识、实际顾问、输入依据和可展开的当轮公开摘要。失败、取消和连接提前结束均不记为完成，也不自动换模型重发。检查服务与对话服务都具有退出清理。

官方协议参考：[Codex App Server](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server)、[模型目录与推理](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)。官方说明 model/list 可能来自内置或缓存目录；目录记录、真实试答回执和本轮完成回答是不同证据。配置中的独立路由仍须取得实际调用回执后才可选。
