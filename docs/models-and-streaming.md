# 可用模型与实时反馈

输入框下方的“本轮模型”只列出经过本工作台真实调用验证的 Codex 和 Gemini 型号。选择只影响下一轮，不更改 Codex 全局默认模型。发送时重新核对可用型号与当前文档权限；取得实际线程模型回执并匹配后才提交问题和资料。

新安装或连接变化后，点击“检查连接”或“连接与留底 → 检查可用模型”。检查使用固定的公开测试句，不发送用户草稿、知识库或个人资料。依次检查本机显式默认模型及 Gemini 候选；每个有时间上限，可停止。只有成功的型号进入列表，失败项留在检查结果。历史成功回执显示验证时间，不等于永久可用或额度保证；验证文件属于私人数据，不随源码分发。

主工作区通过 app-server 的持久 thread/turn 继续对话，不再仅拼接最近12条消息。传输进程按调用释放，持久线程标识保留。资料按需要通过受限动态工具检索、读取；实际读取记入资料证据；完整读取顾问 Skill 后，模型通过 select_advisor 明确选用并给出理由，才进入“本轮顾问”。读过与选用分别记录。不会为每个问题预先强制调用一次独立选顾问模型。

实时反馈区分应用工具事件、模型主动提供的公开工作说明/摘要、回答正文。原始内部思维内容不转发，没有公开摘要时不使用固定文字冒充。流式内存快照有节流，工具完成后保存检查点，普通正文定期保存，降低持续输出对本机的负担。

历史消息和会话列表按游标分页查询；这只是界面加载方式，不会删除底层消息或缩短持久模型线程。取消、失败和重启中断均保留实际状态。

完成消息保留模型标识、实际顾问、输入依据和可展开的当轮公开摘要。失败、取消和连接提前结束均不记为完成，也不自动换模型重发。检查服务与对话服务都具有退出清理。

官方协议参考：[Codex App Server](https://learn.chatgpt.com/docs/app-server)。model/list/配置目录只是候选目录；本工作台额外要求实际完成调用回执后才显示为可选。
