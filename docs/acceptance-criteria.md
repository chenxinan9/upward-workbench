# 需求追溯与验收用例

基线：product.md v1.0，2026-10-06。此文件是验收标准，不是测试结果。实际结果另留回执，注明代码版本、测试时间、输入、输出、证据及未测项。

## 验收规则

- 验收代理不得只读开发者自述；通过真实页面/接口使用路径验证。静态检查、接口测试和浏览器体验各承担自己的范围。
- 关键路径使用隔离测试资料。测试记录与虚构信息不得混进本人当前目标、知识库或公开真实使用案例。
- 以下用例均为本轮必需。安全、隐私、伪装成功、真实集成不可用、持久化丢失为阻断缺陷；其他影响核心可用性的缺陷同样须修复再复验。
- 未通过写明具体问题与复现步骤，返回实现者；复验引用原缺陷 ID，核对修复和受影响邻接路径。不得把“已修代码”当成“已复验通过”。
- 验收通过与用户认可、对外发布分别记状态。

| A02 / R01 | 抽核所有首批提醒的来源及表达类型 | 原话可逐句核对；译文说明翻译，归纳明确归纳；不可追溯条目不作为原话展示 | 提醒清单与核源记录 |
| A03 / R02 | 一句话创建虚构目标，添加行动，编辑、暂停、恢复、完成 | 操作生效且页面一致；进度不靠假数据；可区分结果自报与证据 | 浏览器交互与存储回读 |

## 独立角色与交接

产品需求代理维护本标准；调研代理给出现有工作台、真实集成能力和上游复用证据；实现者交付代码及自测；工作台审计代理查功能、安全与数据边界；验收代理执行上述真实路径；公开包审计代理独立审查最终包，而不是只看源目录或 .gitignore。

返工时保留缺陷 ID、原问题、修复版本、复验结果及剩余边界。增加/缩减需求必须在产品基线注明原因，不能为通过验收静默删除困难用例。
