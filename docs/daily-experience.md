# 日常体验设计与验证边界

本页记录日常体验实现与复用时的检查范围。本轮已完成本机部署；公开发布和用户主观认可另行记录。使用说明见 [daily-use.md](daily-use.md)，写入协议见 [conversation-capture.md](conversation-capture.md)。

## 页面和主路径

| 页面 | 主用途 | 日常入口 |
| --- | --- | --- |
| 我的今天 | 今天要处理的行动、待重排事项与继续阅读 | 本人输入后一键开始讨论；空输入只进入聊天 |
| 人生全景 | 本人愿景、当前阶段、长期条件和历史变化 | 回读来源；带方法打开独立讨论草稿 |
| 目标与计划 | 已决定的阶段结果、步骤、日期和实际结果 | 查看与调整既有目标；候选仍需本人采用 |
| 与 Codex 协作 | 带相关目标和资料讨论，留下明确决定 | 一次点击发送；可选查看发送依据 |
| 顾问书房与知识库 | 读原文、写理解、回读经验并用于问题 | 阅读草稿与位置恢复；带原文讨论 |

聊天默认带进行中与暂停目标，回复后整理目标与记录，选项在输入区可见。模型先选相关顾问，本机读取并校验真实 Skill，随后综合回答；技能目录、实际读取和答案质量分别判断。新增与更新都需核验本人原话，真实结果由回执显示。

输入按数据空间与会话保存；发送时续写、跨页、会话切换、欢迎快捷问题和阅读入口均应保留原稿。等待显示真实阶段与耗时，可停止；正文完成后整体显示，尚无逐字流式输出。状态轮询使用游标，未变化时不重复返回整段历史。上翻阅读时应保留位置，并提示有新回复。

## 源码回归范围

在源码根目录运行：

```sh
python3 -m unittest discover -s tests -p 'test_experience.py'
python3 -m unittest discover -s tests -p 'test_existing_updates.py'
node tests/test_chat_experience.cjs
node tests/test_frontend_steps.cjs
node --check web/app.js
```

| 检查 | 应覆盖的行为 | 证据边界 |
| --- | --- | --- |
| 后端体验与更新测试 | 发送快照、状态游标、已有行动与目标更新、歧义拒写、版本与持久化 | 隔离数据测试不代替真实模型、浏览器与部署验证 |
| 前端真实函数测试 | 会话隔离、发送双击、续写、网络不明的明确重试、异步不串会话、资料持久化、回执同步、首页发送、全景和欢迎草稿保护、IME、阅读位置 | VM 执行实际函数；简化 DOM 不证明布局、滚动、选中文字或真实点击体验 |
| 目标编辑回归 | 保存与失败保留、行动字段保留、候选状态、来源与版本冲突 | 代码回归不代表模型每次都能正确理解指令 |
| 语法检查 | 前端脚本能被解析 | 不证明网络、状态或体验正确 |

复杂指令可能被保守拒绝，特别是否定、同名对象、多日期、假设、转述或版本过期。任何失败都须保持原记录并给出真实原因，不把模型文字中的“已完成”当作保存证据。
