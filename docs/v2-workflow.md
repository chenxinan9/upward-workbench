# 从个人资料到可执行工作台

本流程用于复用本项目。公开包不携带原作者的档案、目标或宣传创作素材；每位使用者在自己的私人目录建立方案。

## 先读资料，再做产品

1. 找到当前使用的工作台、执行规则、既有目标主记录。浏览真实页面并记录间距、字号、导航、首屏重点和输入流程，不能仅凭一句“蓝白风”声称参考。
2. 对自己授权的资料建立来源表：相对路径、日期、证据类型、读取范围与 SHA-256。本人自述、设备报告、历史 AI 判断和已经确认的结果分别标明；后来的纠错覆盖旧推断。
3. 把生活方向整理成领域，而不是立即排满日程。每个领域写已有事实、未知项、现实约束、可调整方案、行动步骤和完成证据。没有记录不代表没有行动；过去目标不自动变成当前承诺。
4. 接入既有目标台账的只读视图。本人主动采用后，工作台保存执行目标及来源快照；旧台账仍保持原状态，不假称自动同步。确认后的工作台行动和旧台账日期需要分别识别。

## 私人连接结构

所有路径放在源码外数据目录的 `settings.json`，不提交此文件：

```json
{
  "growth_plan": "/path/to/private/growth-plan.json",
  "private_root": "/path/to/private",
  "scene": "/path/to/your/scene.png"
}
```

`scene` 是本人有权使用的可选 PNG；缺少图片也可使用页面。作者的本机工作台场景图不在分发包中。完整知识库连接另见 [integration.md](integration.md)。

方案最小结构如下，示例中的事实为空，不假冒任何人；由资料研究工作补全后再连接：

```json
{
  "schema_version": 1,
  "generated_at": "YYYY-MM-DD",
  "overview": {"title": "我的成长方向", "lead": "经过资料核对后的当前重点"},
  "source_register": [],
  "domains": [{
    "id": "learning", "title": "学习与实践", "status": "proposal",
    "known_facts": [], "unknowns": ["当前希望解决的具体问题"], "constraints": [],
    "plan_draft": {"title": "用一个小任务检验理解", "why": "先找到真实任务，再决定学习内容", "approach": ["选择问题", "动手验证", "回看结果"]},
    "actions": [{"id": "learning-1", "title": "明确一个要解决的问题", "steps": ["描述对象和限制"], "completion_evidence": ["问题和判断结果的标准"], "status": "proposed", "due": null}],
    "advisor_slugs": ["feynman-perspective"], "source_ids": [], "keywords": ["学习", "理解"]
  }]
}
```

本地文本来源 `source_register` 条目用 `id/title/path/date/evidence_type/sha256`，path相对private_root；受控读取只接受md/txt/json/docx并检查实际路径。公开来源用 `root:"web"/url/read_scope/checked_at`，展示明确的出处说明，不假装是已下载网页全文。实际原文哈希变化时提醒重新核对。

## 日常闭环

- 首页：每日有来源提醒、目前值得考虑的行动、领域地图和已有台账状态。
- 目标：先回看方案和依据，调整已拟好的步骤，再主动采用。保存不可变来源快照，重复采用同领域不会悄悄新建重复目标。
- 学习：打开顾问方法及参考材料，记录阅读位置、自己的理解、关联目标和实际运用结果。“已实践”须有结果文字，不等于效果已被独立证明。
- 讨论：按具体问题在本机检索，先看材料、移除无关项，再预览实际发送的截取正文与历史。关键词匹配不等于全库语义理解。模型回答可经本人核对后形成目标或行动。
- 复盘：主线、瓶颈、学到的内容、实际结果和下一步分别记录，允许结果未知。写入记录后可转行动；统一知识库接入成功必须回读索引正文和哈希。

## 让审计真正改变产品

产品研究与实现不自行宣布整体通过。独立审计必须复现失败输入，例如同一回答拆成两个动作、来源文件改变、学习记录解除关联、检索失败、重复点击、工具配置异常、未授权路径和重启。

本次 v0.2 返工已发现“同一回复第二个动作被静默丢弃”“采用目标缺来源版本”等问题。修复必须由发现者用原输入复验。界面另按真实首屏、目标已有内容、学习到行动、对话预览和窄屏检查；代码测试通过不代表用户认为好看或满意。

## 分发而不泄露

公开源码与私人运行目录物理分开。构建器只打包明确文件及51份已审阅缩编技能，生成逐文件哈希。审计最终 ZIP，确认没有真实档案、对话、计划、数据库、场景素材、私人截图或宣传创作资料。统计分别列来源、缩编技能、去重方法、使用流程和提醒，不能互相凑数。通过只代表特定本地候选包的检查，不授权上传。


## 将私人方案导读接入现有索引

`tools/plan_index.py --plan /path/to/private/growth-plan.json --output /path/to/private/planning/guide.md` 只生成带方案哈希和日期的私人派生导读。把该目录作为一个独立私人集合交给已有文本索引器；不要索引整个测试/过程目录。方案改变后先重生成导读，再重建索引并核对SHA。派生导读不是新的事实主记录，工作台实际目标进度仍在私人数据库。
