# 成长顾问工作台：调研依据与实施建议

核对日期：2026-10-06。本文件是可复用的方法记录，不包含个人档案、设备路径、原工作台代码或创作宣传稿。实际实现及测试结果以交付记录为准。

## 从现有工作台提炼的设计要求

已只读检查参照工作台的实际页面、当前样式计算值、页面源码与连接代码。当前页面是浅色背景、固定侧栏、白色内容卡、蓝色主行动，首页优先“继续上次”，其次是来源与实际状态；源码中还留有旧主题，不能凭文件开头认定当前设计。实时 DOM 和计算样式已读取，截图捕获超时，未用截图成功作为证据。

成长工作台应继承这些交互原则，而非复制原工作台个人内容：

1. 首页只突出今日提醒、最重要的下一步、继续上次学习或讨论。顾问金句有出处、翻译标识及一项可选的思考提示。
2. 导航围绕今日、目标与计划、顾问与学习、想法与知识、Codex 对话。连接诊断与审计记录放次级入口，避免实现细节塞进日常流程。
3. 自然语言记录想法；目标和计划只要求必要信息。已有资料能带入就不让用户重复填表。
4. 目标、行动、学习和想法共用稳定 ID，保留关联。一次操作后可以回到上下文，不创建相互竞争的目标清单。
5. 学习来源可以回读；显示实际检索片段及来源，而不是把顾问卡片数量冒充学习内容数量。
6. 已保存、已索引、已发送、Codex 已完成、用户采用分别表示真实事件。只有实际产物和回执能推进状态。
7. 私有数据与可发布程序分离；公开演示用明确标识的虚构样例，不复制个人档案、对话、文件名或本机配置。

## Codex 接入研究

本地核对的 CLI 版本为 0.153.4；已读取 `codex exec --help`、`codex app-server --help`，并用内建生成器生成协议 JSON schema，未通过调研向模型发送个人资料。官方说明可见 [非交互运行](https://developers.openai.com/codex/noninteractive) 与 [App Server](https://developers.openai.com/codex/app-server)。

### 最小可运行方案

采用本地后端调用 `codex exec --json --ephemeral`，通过 stdin 传入本次明确选用的材料和本地会话历史，参数以 argv 数组传递。一个本地 conversation ID 管理多轮历史；每次实际调用使用独立 request ID，保存状态、开始结束时间、退出码、必要事件和上下文摘要。

这是“工作台本地会话，逐轮调用 Codex”，不能宣传成续接桌面现有聊天。CLI 的 provider 与认证来自用户当前配置；后端不得把密钥、配置内容或环境变量返回浏览器。当前环境可用不等于其他安装者已经可用，首次启动必须显示检测结果。

文本咨询默认只读、关闭 shell、exec、浏览器、MCP、技能自动注入、自动记忆及额外项目指令。只读沙箱本身仍可能允许读取；必须落实工具禁用并审计实际事件，不仅靠提示词承诺。功能允许的用户请求通过本次发送触发，不应在页面加载、自动重连或失败后偷偷重发。需要额外工具时另行实现明确范围，不能悄悄扩大权限。

成功必须同时满足有效完成事件、非空最终回复、正常退出且无失败事件。进程启动、收到部分文本、测试假响应均不等于成功。超时、取消、429、登录失效、配置错误、工具越界、解析失败需保存用户输入和已收部分文本，显示失败原因；显式重试产生新 request ID，不把失败覆盖成成功。对同一会话的并发发送要串行或拒绝，避免历史交叉。

网页后端只监听回环地址，核对 Host/Origin、请求体与授权边界。静态文件和下载接口限定路径，不能让浏览器提供任意本机文件路径或 CLI 参数。输出 HTML 转义，禁执行模型返回脚本。提示词与日志都属于私有数据。

### 需要原生会话协议时的扩展

本机生成的 schema 验证 app-server 可以通过 stdio：`initialize` → `initialized` → `thread/start` 或已绑定 ID 的 `thread/resume` → `turn/start`。处理 `item/agentMessage/delta`、`turn/completed`，校验 thread 与 turn ID，遇未知工具/审批请求停止。不能使用最近一个聊天或浏览器任意传入的 thread ID。此路径维护成本更高，本期不必为了形式完整而采用。

## 知识库回写与验收

随手记先本地保存；用户点选纳入知识库时，产生保留来源和时间的文档，更新索引，再用刚写入的独特词检索并回读。只有回读内容与保存正文一致才标为“已索引”。若写入成功而索引失败，必须显示两种状态，允许重试，且不重复产生文档。若采用保存即入库，按钮名称应明确写出“保存并入库”。

模型建议与用户事实分开，金句和学习笔记不自动成为用户画像。更正记录保留原版本和修改时间；删除、导出和备份具有明确范围。公开包不包含数据库、运行日志、截图中的私人内容及宣传创作资料。

## 金句出处规范

根目录 `quotes.json` 提供 7 条带来源、定位、核对日期与类型的短提醒。类型区分原文节选、自译与意译；思考题是项目原创，不能拼接后冒充人物讲话。人物卡片是方法参考而非真人在线或授权代言。原始作品及网站保留原权利，不因本项目开源自动获得全文再分发许可。

轮播按用户本地日历日期选择，刷新当日不应随机换人；每日提醒是进入行动和原文学习的入口，不替代目标管理或事实判断。尚未核对来源的语录不得自动加入。

## 独立验收必须提供的证据

- 冷启动和刷新恢复：自建想法、目标、行动、学习记录均可回读。
- 路径闭环：金句→顾问内容→记录想法→入库→检索命中；目标→计划→完成→复盘。
- 真实对话：至少一次真实模型完成与一次可控失败；测试数据与用户资料隔离，不以 stub 通过声称连通。
- 权限失败：跨域请求、任意路径、脚本注入、重复请求和越界工具不能静默成功。
- 统计口径：人物视角数、功能技能数、方法文档数与知识片段数独立计算，有生成日期；不能称全部技能为不同人物。
- 开源包独立审计：代码与方法可复用、依赖可安装、第三方许可证逐项核验。不可再分发内容只提供来源/获取方法，不把个人私有资料或内部使用许可证文件混入发布包。
