# 对话怎样真正使用顾问技能

默认流程：输入问题 → 一次点击发送（内部建立预览快照）→ 语义选择相关顾问 → 读取真实 Skill → 综合回答 → 整理本轮明确记录。用户不需要手动挑选顾问。

## 两次模型调用

1. 选择器读取当前可用顾问的名称、领域、真实技能描述与文件哈希，结合本轮问题、已有会话最近历史和用户选中资料的必要摘录，优先选 1—3 位互补顾问，最多 4 位。它不回答咨询，也不执行工具。
2. 本机程序校验所选名称属于预览目录，读取每份 SKILL.md 的完整正文并验证哈希。最终模型结合真实方法、用户问题和已选资料，给出综合判断。不会把人物当作真人在线，不以逐个扮演名人代替回答。

全库可供选择不等于每轮读取所有顾问全文。目录数量从本机实时生成；本机个人版与公共精简版数量可不同。方法的附属参考书或链接不会因为 Skill 提到它们就自动读取；若另选入参考材料，会在发送依据中列出。

## 可核对的依据

可选的“查看发送依据”显示候选目录；运行阶段显示选择、读取、回答；回复下方显示当轮实际选中的顾问、理由、读入正文、字符数和 SHA-256。历史回复使用当轮保存的最终发送快照，后来的文件变化不改写旧证据。

选择失败、空选择、目录外名字、文件变化或读取失败会明确失败，不退回没有方法的普通回答。两阶段都支持取消和超时；失败不自动重发。模型失败时可恢复问题后重新发送，内部建立新快照并重新调用模型；发送网络结果不明时，明确重试沿用原快照，避免重复请求；已有有效整理结构的保存失败只重试写入。

## 范围与成本

两阶段增加一次短模型调用，但避免每次发送整库全文。运行记录保存真实耗时及 CLI 返回的用量，不预测速度或伪造 token。服务与模型状态会影响延迟，Skill 本身不能保证每次回答正确。

只有选中的私人资料、选择带入的目标和本会话历史被提供；不会额外扫描私人知识库，不会监听其他 Codex 会话。对话中的目标和笔记整理仍单独核验并给真实保存回执。
