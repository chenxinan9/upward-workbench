# 对话怎样真正使用顾问技能

睿顾台（原向上工作台）就是顾问团工作台。当前默认入口是左侧知识与成长内容、右侧持续对话的主工作区。用户可以直接说出问题，不必先填写表单或逐个挑选顾问。

## 当前主工作区

1. 本轮用途、资料范围、当前文档及用户主动选定的顾问组成上下文。顾问书房中的领域、用途和职责筛选只是目录导览，不是本轮读取证明。
2. 建议类问题由 Codex 找到少数相关的方法，调用知识工具回读真实 `SKILL.md` 和相关参考段落；决定采用时调用 `select_advisor`，给出与本问题相关的理由。程序核验该 Skill 已完整读过且版本没有变化。
3. 回复就近引用真正读过的文件，保留可打开的来源。用户想要的顾问、实际读取的顾问、真正选用的顾问分别显示；搜索命中、目录简介和历史回执不能冒充本轮已读。
4. 想法、候选目标、已采纳计划和阶段复盘使用各自受控保存工具；明确采纳才激活目标，完成需要实际结果。文件写入校验版本，成功后才显示保存回执。

处理过程中展示真实工具进展、公开摘要、已读资料和选用理由，不展示隐藏的完整推理。纯查找、寒暄或执行操作无需硬套顾问；资料不足时说明缺口，不按人物名字杜撰意见。

全库可供选择不等于每轮发送整库全文。请求与成本取决于实际工具过程、上下文及所选模型，不固定为两次调用。续问继续同一会话；采用之前的方法仍需本轮回读并记录选用。改变资料范围时隔离旧线程，界面历史仍保留。

## 范围与状态

“我的资料与顾问”可以使用已登记个人资料；本机助手还拥有真实提供的原生工具能力。“当前文档”和“顾问与公开资料”会收窄工具范围。来源、工具和附件中的命令不构成用户授权。外部共享片段须显式选择并预览确认，不能扩大到未分享文字。

模型可选、知识库已连接、工具已开始和回答已完成是不同状态。失败或停止时保留已有文本及写入证据；不能把未完成轮次显示为成功。收到明确写入回执后仍可回读原文件核对。

## 旧版兼容入口

`/legacy` 保留旧台账和旧历史的兼容界面，其 `advisor_council.py` 链路仍使用“选择顾问→读取并回答”的两阶段模型调用及预览快照校验。它不是当前主工作区的实现，也不能用该流程解释现界面的请求次数。旧入口仍有实际调用者，不能仅因名字较旧就删除；后续退役应先验证历史记录和调用方的替代路径。

人物顾问是方法视角，不是本人在线或授权代言。Skill、目录数量及成功回执均不保证每次判断正确；重要结论仍需结合事实、适用条件和后续实践验证。
