# 使用自己的 Codex 或 DeepSeek

睿顾台可以在同一聊天中选择 Codex 或 DeepSeek。顾问、知识检索、受控写回和成果查看使用同一套工作台功能；模型不同，实际效果、图片和联网能力可能不同。切换模型不会删除聊天。下一次发送时，所选服务可以承接当前资料范围内的既往对话。

## 先选一条接入方式

| 你已有的服务 | 需要做什么 | 用谁的额度 |
| --- | --- | --- |
| ChatGPT 中的 Codex | 在自己电脑安装并登录 Codex CLI | 自己登录的 ChatGPT 账户；具体额度按账户方案 |
| DeepSeek 开放平台 API | 在自己电脑安装 Codex CLI 作为工具引擎，再在睿顾台保存自己的 DeepSeek API 密钥 | 自己的 DeepSeek API 账户，按其规则计费 |
| 只有 DeepSeek 网页或手机 App | 先到官方开放平台申请 API 密钥 | 网页/App 账号不能直接当作 API 密钥 |

**安装包不提供作者账号、登录状态或 API 密钥。** 使用 DeepSeek 路线不要求登录 ChatGPT，也不要求购买 ChatGPT Pro。两种路线都需要可运行 `codex app-server` 的近期 Codex CLI，CLI 在这里提供本机工具与会话引擎。

## 安装与启动

先按[上手说明](getting-started.md)建立自己的工作区。阅读、编辑和检索本地内容不需要模型登录。

Codex CLI 的安装方式以[官方 Codex 文档](https://learn.chatgpt.com/docs/cli)为准。已装官方桌面应用的 macOS 电脑也可能有可用的内置 CLI。若工作台未发现程序，可以在私人 `settings.json` 中指定 `codex_cli` 的绝对路径，再重启工作台。不要复制别人的认证目录。

## 接入 DeepSeek（macOS）

1. 在 [DeepSeek 官方开放平台](https://platform.deepseek.com/)创建自己的 API 密钥，并确认账户可用。
2. 打开睿顾台右侧的对话设置，进入“模型与连接”。
3. 在 DeepSeek 的密码输入框粘贴密钥，点击保存。密钥保存到本机系统钥匙串，按当前工作区分别登记。保存成功只表示已安全保存，不表示已经试答成功。
4. 刷新模型列表，选择带 `DeepSeek` 名称的模型。发送一条不含私人资料的简单问题，核对实际回复和服务标记。
5. 以后直接在输入框的模型选择器切换服务，无需新开聊天或重新介绍背景。

系统钥匙串如请求本机授权，应由电脑使用者处理。不要把密钥发到聊天、Issue、截图或演示视频里。删除连接会移除本工作区的钥匙串记录，旧聊天仍可阅读；不会自动切到另一个服务代发。

## Linux 启动环境

Linux 不在界面保存明文密钥。可在启动服务的同一个 Bash 终端用隐藏输入设置变量，避免将实际值写入命令历史：

```bash
read -rsp 'DeepSeek API key: ' RUIGU_DEEPSEEK_API_KEY
export RUIGU_DEEPSEEK_API_KEY
python3 app.py --data-dir "$HOME/UpwardData" --port 60129
unset RUIGU_DEEPSEEK_API_KEY
```

变量属于本机启动环境，不是项目配置；不要把它写入仓库、共享启动脚本或公开 `.env`。正式使用可用自己系统的凭据管理器注入环境。此路线的跨平台实际验证范围见发布验收说明。

## 模型名称与能力

截至 2026-10-25，官方接口 `deepseek-flash` 对应 **DeepSeek V4.1 Flash**，官方价格页列出的版本为 `DeepSeek-V4.1-Flash-1017`；另有 `deepseek-v4-pro`。界面同时说明服务与模型，不用旧版 `deepseek-chat` 或 `deepseek-reasoner` 冒充当前接口。版本会更新，以[官方模型说明](https://api-docs.deepseek.com/quick_start/pricing/)为准。

Flash 支持图片输入，当前 Pro 接口只支持文本。文本附件由本台解析后提供给模型；模型不支持的图片应明确提示并保留附件，不能静默丢弃。联网等能力还取决于模型接口和本机工具，并不等于完整复制 Codex 桌面应用。

打开设置和刷新目录不发试答；明确的连接试答及日常发送才会调用模型。界面须区分“凭据已保存”“目录信息”和“已实际回答核验”，不能把其中一种当成全部成功。

## 同一聊天切换模型

Codex 和 DeepSeek 共用本台聊天记录。下一次发送时，当前服务可以收到当前资料范围允许的、有长度上限的既往问答；很长的历史不保证逐字保留。后台的服务认证和服务端线程仍分别管理，不能把一家的线程编号直接提交给另一家。

切换服务不会扩大“我的资料与顾问 / 当前文档 / 顾问与公开资料”的权限，也不把之前的共享授权挪给另一家。已共享片段的发送确认要显示本次实际接收服务。范围收窄、换文档及共享撤回等原有边界继续有效。

只有主动发送或模型调用允许的工具后，相关内容才传给所选服务。不会同时把每个问题发给两家，不会在失败后静默换服务重试。原生工具可操作当前系统权限允许的内容，需照常核对本机操作和审批。

## 凭据与公开包

macOS 的真实 DeepSeek 密钥由主服务从钥匙串读取，不进入源码、聊天提示、普通日志、模型目录、浏览器恢复存储或 Codex 子进程的参数与环境。子进程仅取得本轮短期转发令牌；真实密钥只由本机服务发往固定 DeepSeek 官方 HTTPS 地址，不跟随跳转。钥匙串记录不在普通数据目录备份中；换电脑或改用新数据目录后需要重新接入。

Codex 继续使用安装者本机的认证。项目不会导出 `~/.codex/auth.json`、钥匙串或作者账户。仅忽略文件名不足以证明安全，公开前还需对白名单、Git 改动与精确 ZIP 进行审计。以上措施不能阻止同一系统账号下已有充分权限的其他程序访问其可读内容。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 密钥保存成功，但回答失败 | 核对账户余额、网络及官方服务状态；保存成功不是试答成功 |
| DeepSeek 模型无法发送 | 检查本机 CLI、钥匙串授权或启动环境，不要复制他人认证 |
| 图片不能发送给 Pro | 换用支持图片的 Flash，或移除图片后发纯文本 |
| 切换后要重新确认共享片段 | 本次接收服务已变化，需要按实际服务确认 |
| 换电脑后没有连接 | 凭据不随公开包或知识库迁移；用自己的密钥重新接入 |

协议依据：[DeepSeek 官方 Codex 接入](https://api-docs.deepseek.com/quick_start/agent_integrations/codex/)、[Responses API](https://api-docs.deepseek.com/guides/responses_api/)、[Codex 认证与计费方式](https://learn.chatgpt.com/docs/auth)。睿顾台使用独立服务配置，不要求执行会修改全局 Codex 配置的第三方安装脚本。
