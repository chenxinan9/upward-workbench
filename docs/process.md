# 实施过程与复用方式

历史基线：v0.1.0。本次返工及复用见 [v2-workflow.md](v2-workflow.md)、当前检查见 [v2-validation.md](v2-validation.md)。以下保留初轮过程，不能将其判定扩大为完整原诉求通过。

目标是交付本机可操作的成长工作台，而非顾问名单或展示壳。

## 角色与交付物

| 角色 | 职责 | 可复用记录 |
|---|---|---|
| 产品需求 | 将个人诉求抽象为可验证功能，限定不把旧愿望激活成承诺 | product.md、acceptance-criteria.md |
| 调研 | 查看实际旧工作台，核对本机 CLI 与来源内容 | research.md、quotes.json |
| 主实现 | 本地数据、页面、顾问阅读、对话与知识库连接 | app.py、web、tools、tests |
| 工作台审计 | 独立检查数据一致性、路径与调用边界 | audit-plan.md、audit-findings.md |
| 独立验收 | 使用隔离资料走真实浏览器和故障路径，缺陷返工复验 | validation.md |
| 分发审计 | 检查来源许可、实际候选 ZIP、隐私与白名单 | distribution-policy.md；最终包审计回执与 ZIP 一起交付 |

## 两条可追溯样例

**从需求到可用功能：** R05 要求真正与 Codex 对话 → 调研确认本机 `exec --json --ephemeral` → 实现选择资料与历史内容预览 → 初审 WB-05 发现只显示历史条数 → 修为显示实际发送的历史正文 → A09/A11 以无隐私短语验证真实响应、双轮历史和选取范围。模型失败不是成功，CLI 警告也不单独等同本轮失败，必须联合解析回合事件与退出码。

**从缺陷到复验：** A15 在隔离顾问目录把 `SKILL.md` 链接到目录外 → ACC-003 证明读取边界不足 → 实现比较解析后的文件与授权目录 → 加入自动回归 `test_advisor_symlink_refused` → 独立验收重跑原输入。不得把“写了检查”当“已独立复验”。

## 下一位复用者的顺序

1. 写清自己的当下场景、历史参考和成功标准，不先填一堆目标。
2. 准备有来源的顾问目录，按许可证逐项处理，正文与执行程序分开。
3. 在空库跑通保存、检索和真实对话，再连接私人资料。
4. 用虚构记录复现失败、重启、并发、恢复、跨站和越界输入。
5. 让独立角色依据标准复验，保留未通过与修复证据。
6. 只从白名单生成公开候选包，按最终文件再次审计。

用户真实经历、收入、健康、对话、既有历史方向与宣传创作内容不属于公开实施样例。真实截图与原始模型回执可能含本地环境信息，应留在私人证据区；公开结论只陈述验证范围。
