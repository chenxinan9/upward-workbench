# 个人成长顾问工作台 · 产品需求

版本：1.0。日期：2026-10-06。状态：需求基线，尚不代表实现、验收或公开发布。

## 1. 产品要解决的问题

让一个人把长期方向、近期行动、日常想法与可信的顾问资料放在同一工作流里：打开首页得到有出处的提醒，知道眼下最重要的事，随手记下想法，需要时与 Codex 讨论，把有价值的记录与结论归入自己的知识库。工作台应减少管理负担，而不是让用户再维护一套表格。

通用代码、通用方法、可合法再分发的顾问技能、匿名演示数据和复用文档组成可开源产品；个人档案、真实记录、账户配置及创作宣传材料在其外部单独保存。可开源交付与实际对外发布是不同状态。

## 2. 从既有工作方法继承的要求

- 使用唯一主记录和稳定标识。页面是同一资料的视图，不能复制出互相矛盾的目标、日志或学习记录。
- 按当前问题读取最小相关上下文，来源、日期、已核范围与缺口可见；不把全部个人档案塞进每一次模型请求。
- 事实、本人陈述、历史目标、待确认建议、AI 推断和演示内容分别标识。历史状态不会因导入而变成当前承诺。
- 研究、实现、实际运行、独立审计、验收和发布分别留证；程序通过不代替真实用户路径验收。
- 缺陷退回产生问题的环节，修复后核验受影响范围；没有新依据不无限重复测试或重建。
- 近期精进保留“现状—卡点—学习—行动—结果复盘”的方法。长期方向用于解释取舍，不强制每天进行战略分析，也不强制生成固定数量的短板、案例或人格评分。

## 3. 页面与核心体验

| 页面 | 用户首先看到什么 | 主要动作 |
|---|---|---|
| 今天 | 每日顾问提醒、本人选定的当前重点、下一步、随手记录入口；下方是可学习的顾问内容 | 记想法、讨论当前重点、开始学习、完成或调整行动 |
| 目标与计划 | 长期方向、当前目标、下一步与结果证据；历史建议单独标识 | 新增/编辑/暂停目标，添加/修改/完成行动，复盘与关联记录 |
| 顾问与学习 | 按问题找顾问，看到方法简介、来源与适用边界 | 筛选、阅读、记录理解、围绕内容发起讨论 |
| 想法与知识 | 自己的想法、讨论结论、学习笔记；入库与索引状态明确 | 搜索、编辑、关联目标、归档、入库及回读 |
| 协作与设置 | Codex 连接、知识库位置、资料范围、导出与运行状态 | 发起真实对话、检查故障、选择上下文、管理本地配置 |

首屏保持少量高价值信息，不同时铺开全部顾问与指标。沿用用户已认可的自媒体工作台的信息组织和视觉经验，但不直接复制其创作流程。桌面与窄屏都要可读、可操作；状态不能只靠颜色表达。

## 4. 必须实现的行为

### R01 每日提醒

按用户本地日期选择一条顾问提醒，同一天刷新不无故变化，可主动换一条。作者、作品或文章标题、来源链接/条目以及表达类型一起显示。核对过的原话、译文、意译与本地归纳必须区分；未核实的文字不能加引号冒充名人原话。无合适原文时可以明确显示“方法提醒”。只有实际接入推送或定时器才能称已开启每日通知；按日切换的首页卡片不等于后台推送。

### R02 目标与计划

以一句话建立目标，详情渐进展开，不要求先填完整人生画像。目标至少有稳定 ID、标题、状态、创建和更新时间；计划可关联目标、时间与完成条件。添加、编辑、暂停、完成、恢复至少形成可理解的操作链，不能只创建不能管理。进度来自真实计划状态；主观自报结果与已附证据结果不同。历史导入项默认待核对或参考，不自动变成今日任务。截止日期未知允许空，不伪造倒计时或完成百分比。

### R03 日常记录

同一个自然语言输入框能先保存想法，并提供“与 Codex 讨论”“关联目标”“加入知识库”等明确动作。记录至少保存原文、时间、来源/类型和稳定 ID。原始记录不被模型摘要静默覆盖。刷新或服务重启后内容仍存在；失败不能出现成功提示或丢失输入。用户可以修正、归档记录；破坏性操作提供适当恢复或明确提示。

### R04 顾问学习

顾问卡片来自实际可用目录，数量由当前目录计算，不把未安装候选、合并参考或本地方法章重复计入技能数。卡片能打开真实学习内容及来源，标明人物视角、功能方法与原始著作的区别。按问题检索、领域筛选、开始阅读、记一条理解、关联行动形成完整路径。没有实际阅读证据，不生成“已掌握”或学习时长。常用入口由本人选择或透明规则推荐，不用未知画像下断言。

### R05 Codex 真实协作

工作台内有可用的输入、执行中状态、返回文本和失败反馈。连接状态以实际探测为依据，不把“已配置”显示成“已连接”。用户发送后，真实后端收到请求并返回可核对的执行 ID/会话标识或等价回执；页面呈现回复，并说明本次附带了哪些上下文。讨论不默认触发外部消息、购买、发布、交易或修改用户资料。若只能复制提示词/打开 Codex，必须标为交接功能，且本项仍为未完成，不能验收成已接入对话。

### R06 知识库闭环

复用现有知识库接口和索引；新用户可以建立独立本地知识库。保存记录、已入库、已索引、可检索四种状态按实际链路区分。入库后能通过关键词找到并回读保存的内容；重复提交按稳定 ID 或内容版本处理，避免生成多份同文。编辑后的旧索引不能继续伪装最新。知识库离线/失败时保留本地记录与重试入口，并显示明确原因。

### R07 个人化与权限范围

个人化建立在有日期的事实和当前选择上；未核的旧信息需保留日期和待确认状态。按主题选择必要上下文，允许用户检查和减少附带资料。新用户无需提供健康、财务、家庭等敏感信息即可启动。私人数据保存在公共项目之外，配置示例使用占位符；运行日志、浏览器响应、导出包不得泄露凭据。

### R08 本地服务安全与可靠性

默认只供本机访问。写接口要防止第三方网页跨站写入；读取文件限定在授权资料根与允许的文件类型，拒绝路径穿越和越界符号链接。用户笔记、模型回复及第三方顾问 Markdown 都是不可信内容，不能执行脚本或把其中的指令提升为系统权限。并发写入或重试不会静默覆盖已有记录。启动、关闭、备份与恢复步骤可复用。

### R09 可复用项目与公开包

提供环境要求、启动步骤、功能边界、架构/数据目录说明、测试方式、第三方来源与许可证台账。公开演示使用明确虚构的数据，在干净目录可启动。公开包采用明确白名单生成，不依赖单一 .gitignore；嵌套压缩包、截图、日志、数据库、绝对路径也需检查。可再分发资格逐项核对；仅允许内部使用或权利不清的顾问包不得随项目公开，可记录来源和未包含原因。用户拥有本地使用副本不等于取得上游重新许可权。

### R10 过程与统计留底

需求—研究—实现—审计—修复—验收有一份可追溯记录。产品、调研、工作台审计、验收、公开包审计分别具名；独立审核不得由作者自评冒充。统计注明日期、计算口径和证据：顾问人物数、功能技能数、本地方法数、知识条目数、实际通过用例数、待修缺陷数；未知耗时、费用或模型用量记未知，不能编成零或宣传节省比例。宣传视频策划和本人故事另存在私有目录，不进入公开包。

## 5. 状态与最小数据模型

| 对象 | 必需信息 | 必须区分的状态 |
|---|---|---|
| 提醒 | 内容、作者/归纳者、类型、来源、日期键 | 已核原话 / 译文 / 意译 / 方法归纳 |
| 目标 | ID、标题、来源、状态、时间、可选完成条件 | 候选/待核、进行、暂停、完成、归档 |
| 行动 | ID、目标关联、内容、可选日期、状态、结果 | 待做、进行、已完成；自报与证据说明 |
| 记录 | ID、原文、类型、时间、关联项、版本 | 已保存、入库中、已入库、索引失败、可检索 |
| 对话 | ID、输入、上下文范围、回复、后端回执、时间 | 未发送、运行中、成功、失败/中断 |
| 顾问 | 稳定名称、类型、领域、来源、许可证、可用状态 | 可用、仅参考、未启用、不可再分发 |
| 证据 | 对象关联、来源位置、日期、核验范围 | 已核 / 本人陈述 / 历史参考 / 未核 |

字段可按实现合并，但不得丢失其语义；这些是系统保存字段，不要求用户逐一填写。

## 6. 本轮验收范围与交付边界

R01—R10 为本轮必需范围，细分验收见 acceptance-criteria.md。无需为了数量额外增加社交排行、人格评分、积分兑换、公开用户账户或自动外部发布。语音输入、云端同步、多用户协作、后台通知和移动端安装包可后续增加，未实现就不展示可用开关。

交付必须包含可运行工作台、真实核心链路证据、独立审计与修复结果、独立验收、通过公开包审计的候选发布包、私有过程与宣传素材入口。公开包准备完成不能写成已在 GitHub 发布；最终用户认可单独记录。
